# Lefax Course design-sync notes

## Repo shape
- This repo is an app (Vite + React + Tailwind + Supabase), not a published component library — no `main`/`module`/`exports`, no `dist/index.*.js` + `.d.ts` tree. Synced in **synth-entry** mode: the converter reads straight from `src/components/` (`cfg.srcDir`).
- Because there's no `node_modules/lefax-course` (this repo isn't installed as a dependency of itself), a **directory junction** `node_modules/lefax-course -> .` (repo root) is required so `PKG_DIR` resolves correctly. Recreate it on a fresh clone: `New-Item -ItemType Junction -Path node_modules\lefax-course -Target .` (PowerShell) or `cmd /c mklink /J node_modules\lefax-course .`. It lives inside the already-gitignored `node_modules/`, so it is never committed — this is a fresh-clone setup step, not a one-time fix.

## Scope decisions
- **Excluded `ProtectedRoute`**: a route guard (reads auth context, redirects), not a visual/design-system component.
- **Excluded `BackendBanner`**: imports `src/lib/supabaseClient.ts`, which reads `import.meta.env.VITE_SUPABASE_URL` at module scope. Vite injects `import.meta.env` at build time; a plain esbuild IIFE bundle does not, so this would throw at bundle-load time and break the entire `window.LefaxCourse` global for every component, not just this one. Confirmed with the user (2026-07-21) — accepted as a real exclusion, not a placeholder to revisit unless the repo adds an esbuild-safe env shim.
- **Excluded `BottomTabs`**: it's `lg:hidden` (mobile-only nav), while `Sidebar` — same `TABS` data — is `hidden lg:flex` (desktop-only). `package-validate.mjs`'s render check always opens previews at a fixed 1200×800 page (no per-component viewport hook), so one of the two will always show `rootEmpty` no matter which is authored — there is no single viewport where both pass. Kept `Sidebar` as the representative persistent-nav component and dropped `BottomTabs` rather than hack around the checker (e.g. an iframe sized under the `lg` breakpoint) for one nav variant. Revisit only if a future design-sync version supports a per-component render-check viewport.

## CSS / fonts
- `cfg.cssEntry` points at `.design-sync/.cache/build/entry.css`, generated by `.design-sync/build-css.mjs` (the recorded `buildCmd`) — it runs the Tailwind CLI against `src/index.css` (avoids depending on Vite's content-hashed `dist/assets/*.css` filename) and prepends the Google Fonts `@import`.
- Fonts (Newsreader, Public Sans) are loaded from Google Fonts at runtime via that `@import` — never shipped as local `.woff2` files. This is `[FONT_REMOTE]`, informational only.

## Provider
- Previews wrap in `I18nProvider` (from `src/lib/i18n.tsx`, brought in via `cfg.extraEntries`) then `MemoryRouter` (from `react-router-dom`) — `Sidebar`, `BottomTabs`, `LangSwitcher`, `ScreenHeader` all call `useI18n()`, and `Sidebar`/`BottomTabs`/`ScreenHeader` also need Router context (`NavLink`/`useNavigate`).

## Known render warns
- `Button` (first component alphabetically, so first processed each run) intermittently fails with a spurious empty-render error — seen 3 times across `package-validate.mjs` (`[RENDER]` root empty, maxHeight 0, despite the screenshot showing both stories fully painted) and `package-capture.mjs` (`window.__dsCells is empty`) — always cleared on an immediate retry with no code change, and once graded, "carried forward" runs never re-render it so the flake stops recurring in practice. The compiled `_preview/Button.js` is structurally identical to every other component's. Reads as a cold-start race in the very first headless page of a run, not a real defect. If it ever fails persistently (not clearing on retry), investigate for real rather than re-running blindly.

## Re-sync risks
- `dtsPropsFor` for all 13 components was hand-written (no real `.d.ts` to extract from) — if a component's actual prop signature changes, the hand-written body will silently drift out of sync. Re-check against the source when re-syncing after any prop change to `src/components/`.
- `componentSrcMap` pins every component's exact file path — adding a new component under `src/components/` requires a new `componentSrcMap` entry (or an explicit exclusion), it will NOT be auto-discovered, because pinning any entries here means the auto-derive-from-src fallback never runs.
- The Tailwind-compiled CSS only includes utility classes actually used somewhere in `content: ["./index.html", "./src/**/*.{ts,tsx}"]` (see `tailwind.config.js`) — since that scan covers the whole app, not just `src/components/`, this is safe today, but if `tailwind.config.js`'s `content` glob narrows in the future, re-verify no component classes silently drop out of the compiled CSS.
